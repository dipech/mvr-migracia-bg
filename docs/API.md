# Исследование источника

Исследована публичная страница `https://mvr-migracia.sky.bg/customer.html` 14 октября 2026 года. Скрипт встроен в HTML, использует jQuery и обновляется раз в 3 секунды. Наш клиент опрашивает JSON раз в 5 секунд. В проверенных ответах всех четырёх API присутствует `Access-Control-Allow-Origin: *`. Cookies и прокси не требуются.

| Endpoint | Назначение |
| --- | --- |
| `/customer.json?qr=…` | ticket_id, ticket, service_id, service, статус; error 1 — не найден, 2 — истёк доступ |
| `/service_on_desk.json?service=…` | desks: массив номеров окон услуги |
| `/online-tickets.json?filter=2&qr=…` | data: объект rowN с талонами текущего дня, включая завершённые |
| `/online-desks.json?qr=…` | data: объект rowN со статусами и текущими талонами окон |

Талоны: статусы 0 ожидает, 1 вызван, 2 обслуживается, 3 припаркован, 4 перенаправлен, 8 неявка, 9 завершён. Окна: 4 принимает, 5 работает с клиентом, 7 клиент назначен; остальные не считаются активными. Неизвестные статусы не превращаются в известные автоматически.

Числа часто являются строками. `00:00:00` — отсутствие события. Время талонов обычно без даты, время окон может иметь вид `14.10.2026 г. 10:13:46`. Используется текущий день Софии. Дату выдачи старого QR из одного времени достоверно восстановить нельзя; сохранённые талоны используют дату первого добавления.

## Ошибка официального счётчика

Исходная страница перебирает записи в порядке JSON до собственного ticket_id, считая ожидающих с пересекающимися окнами. Порядок записей не совпадает со временем выдачи; более поздние талоны встречаются раньше более ранних. Поэтому официальный счётчик не является надёжной длиной очереди. Собственный счётчик использует время выдачи с ticket_id как вторичным ключом. Реальные приоритеты и перенаправления могут отличаться от такого порядка.

Официальный прогноз: сумма forecast_time этих записей, делённая на число активных подходящих окон (минимальный делитель 1). Поля people_wait, wait_time, desk_work из customer.json в исследованных ответах нулевые и для расчёта не используются.

## Обезличенный пример

```json
{
  "error": 0,
  "data": {
    "row1": {
      "ticket_id": "101",
      "ticket_num": "C1",
      "ticket_status_id": "0",
      "service_name": "Пример услуги",
      "service_desk": "[10],[11]",
      "ticket_priority": "Нормален",
      "date_time_taken": "08:15:00",
      "date_time_called": "00:00:00",
      "date_time_arrived": "00:00:00",
      "finish_date": "00:00:00",
      "forecast_time": "420",
      "ticket_wait_min": "15",
      "desk_number": "",
      "called": "0"
    }
  }
}
```

API также отдаёт QR других посетителей. Они намеренно не включены в пример и отбрасываются при нормализации. Не обращаемся к endpoint обратной связи и не изменяем состояние очереди.

## Актуальность окон

Печатные номера повторяются даже в один день. Текущий талон сопоставляется с окном по ticket_id, статусу и номеру окна. Завершение собственного талона не прекращает обновление общего табло при наличии QR текущего дня. Данные старше 15 секунд показываются как последние известные.
